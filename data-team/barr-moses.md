## Key Frameworks

### Five Pillars of Data Observability
| Pillar | Question |
|--------|----------|
| Freshness | Is the data up to date? |
| Volume | Is the amount expected? |
| Distribution | Are values within range? |
| Schema | Has the structure changed? |
| Lineage | Where did this data come from? |

### Data Downtime Definition
```
Data Downtime = Time when data is:
- Missing
- Inaccurate
- Or otherwise erroneous
```

### Incident Response Process
1. Detect (automated alerting)
2. Triage (impact assessment)
3. Investigate (root cause)
4. Resolve (fix the issue)
5. Communicate (stakeholder updates)
6. Prevent (systemic improvement)

### Data Quality ROI
- Cost of bad decisions from bad data
- Engineering time spent debugging
- Trust erosion with stakeholders
- Opportunity cost of data distrust

## Key Insights

- **Data breaks silently** - Without observability, you don't know
- **Prevention > detection** - But you need both
- **Lineage enables debugging** - Know where data comes from
- **Trust is earned** - And easily lost
- **Culture > tools** - Tools enable, culture drives
